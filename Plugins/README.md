# SDK плагинов APEX Chatd

Начиная с API `1.2.0`, плагин может включать файлы `Locales/<код>.json` в свой ZIP. Например, `Locales/fr.json`:

```json
{
  "strings": {
    "SettingsTitle": "Paramètres"
  }
}
```

Получайте перевод через `context.Translate("SettingsTitle", "Settings", fallbackLanguage: "en")`. Для `fr-CA` приложение сначала ищет строку в `fr-CA.json`, затем в `fr.json`. Если строки нет, используется указанный запасной язык, затем строка по умолчанию или ключ. Укажите `minApiVersion: "1.2.0"` в манифесте. При сборке добавьте файлы локализаций в вывод публикации. GitHub Updater показывает, как это сделать. Подпись пакета охватывает и файлы переводов.

Начиная с API `1.1.0`, `context.RegisterShortcut(id, title, handler)` добавляет команду во вкладку «Управление». Укажите `minApiVersion: "1.1.0"` в манифесте. Пользователь назначает глобальную горячую клавишу. Обработчик вызывается на потоке интерфейса и получает токен отмены плагина. Сочетание сохраняется по ID плагина и команды и возвращается при повторном включении плагина.

Плагин — библиотека .NET для `net10.0-windows10.0.22621.0`. Добавьте ссылку на пакет `ApexChatd.PluginSdk` или на [проект SDK](../PluginSdk/Chatd.PluginSdk.csproj) с `Private="false"`. При ссылке на NuGet используйте `ExcludeAssets="runtime"`. Приложение предоставляет SDK при загрузке. Локальный NuGet-пакет можно собрать командой `dotnet pack PluginSdk/Chatd.PluginSdk.csproj -c Release`.

Наследуйтесь от `Plugin` и в `Register` объявите возможности. `StartAsync` и `StopAsync` вызываются на потоке интерфейса. Для длительной работы учитывайте отмену. Фабрика вкладки тоже вызывается на потоке интерфейса. Обработчики сообщений работают в фоне в порядке поступления, с отдельной очередью на плагин. При переполнении очереди пропускаются самые старые ожидающие сообщения. Для получения тестовых сообщений передайте `includeTests: true`. TTS-провайдер получает текст и настройки профиля и записывает в предоставленный поток полный WAV или MP3. ID провайдера хранится как `<id плагина>/<id провайдера>`. Сохраняйте эти ID между выпусками.

Каждый ZIP содержит в корне `plugin.json`, DLL и её зависимости. Пример манифеста есть у [GitHub Updater](GitHubUpdater/plugin.json). Укажите ID, версию, имя сборки и полный тип входа, а также `minApiVersion` и `maxApiVersionExclusive`. `minAppVersion` можно добавить, когда требуется конкретная версия приложения. Поле `tabIcon` задаёт один символ Segoe Fluent Icons для вкладок плагина. Версии задаются как `major.minor.patch`. Пользователь устанавливает ZIP через вкладку «Плагины». Изменения вступают в силу после перезапуска.

В `updateUrl` можно указать HTTPS-адрес JSON с полями `id`, `version` и `releaseUrl`. По кнопке менеджер проверит версию и предложит открыть HTTPS-страницу выпуска. Проверка работает и для выключенного плагина.

Из корня репозитория соберите отдельные ZIP в PowerShell:

```powershell
.\Plugins\build-package.ps1 -Project Plugins/GitHubUpdater/GitHubUpdater.csproj -OutputDirectory bin/Plugins/GitHubUpdater -Zip bin/Plugins/GitHubUpdater.zip
```

Каталог публикации должен быть новым. Edge TTS собирается в [отдельном репозитории](https://github.com/Tor-del/APEX-ChatD-Plugin-EdgeTTS). Его пакет включает исходники и лицензии сторонней библиотеки. Чтобы проверить собственную пересборку этой библиотеки, замените её в локальной копии пакета и пересоберите неподписанный пакет с обновлёнными хешами. Установщики с GitHub включают GitHub Updater. Сборка с Edge TTS предлагает установить его отдельным флажком, включённым по умолчанию. Основной проект можно публиковать отдельно для упаковки в MSIX.

При одобрении отдельного выпуска соберите пакет с `-SigningKey <private.pem>` в PowerShell 7. Скрипт записывает хеш SHA-256 каждого файла в манифест и подписывает его байты RSA/SHA-256. APEX Chatd по умолчанию встраивает открытый ключ из [Assets/plugin-approval-public.pem](../Assets/plugin-approval-public.pem). Для локальной проверки с другой парой ключей можно указать `-p:PluginApprovalPublicKey=<public.pem>` при сборке приложения или `-PluginApprovalPublicKey <public.pem>` при сборке установщика. Плагин получает статус «Проверен APEX Chatd», когда подпись соответствует встроенному ключу и все файлы проходят проверку.

При публикации тега `v<версия>` GitHub Actions передаёт секрет репозитория `APEXCHATD_PLUGIN_SIGNING_KEY` в сборку установщика. Она проверяет соответствие ключей и подписывает GitHub Updater. Сборка с Edge TTS загружает подписанный ZIP последнего релиза плагина и проверяет его подпись перед включением в установщик. Для локальной сборки того же установщика передайте путь к закрытому ключу через `installer/build.ps1 -PluginSigningKey <private.pem>`. Обычные проверки веток и PR собирают установщик с неподписанными пакетами.
